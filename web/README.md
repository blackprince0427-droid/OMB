# 小型辦公軟件

網頁版，對應 OMB 開發文檔 DEV-V1、UI 規格 UI-DEV-V1、第二版內容 DEV-V2-CONTENT（依據計劃書 V1.14）、第三版內容 DEV-V3-CONTENT（依據計劃書 V1.16），第四版內容 DEV-V4-CONTENT（依據計劃書 V1.20），第五版修復 DEV-V5-FIX（依據計劃書 V1.22），第六版內容 DEV-V6-CONTENT（依據計劃書 V1.24，F-24～F-27），以及第七版內容 DEV-V7-CONTENT（依據計劃書 V1.25，F-29～F-30）。桌面版先不做。

## 開啟

用瀏覽器打開 [http://localhost:43123](http://localhost:43123)。預設帳戶與密碼都是 `CEO`。

網頁若尚未啟動，在 `web/` 執行：

```bash
npm install
npm run open
```

目前這個網站的資料屬於「預設公司」，預設帳戶與密碼都是 `CEO`。登入狀態存在 `sessionStorage`（鍵名 `osp-dev-v1-session`），留在目前這個分頁。可在「帳戶」登出並返回登入頁。公司、各公司的帳戶與工作資料存在 `localStorage`，鍵名是 `osp-dev-v4-companies` 與 `osp-dev-v4-bundles`。清除這個網站的資料後，會回到預設公司的 CEO 帳戶。

## 固定網址（Vercel）

線上交付是固定網址的網頁。推送到 GitHub 的 `main` 之後，Vercel 會自動重新建置並更新那個網址。資料仍只在該瀏覽器的 `localStorage`／`sessionStorage`（換瀏覽器或清掉網站資料就沒有了）。沒有後端，也沒有跨裝置同步。

倉庫裡還沒有接上 Vercel。要上線必須先由心夜同意合併部署設定，再到 Vercel 做一次連接。連接完成後，之後每次推上 `main` 就會自動更新，不需要再改專案設定。

這次開發機上的 Cloudflare 臨時網址只在該次會話有效，不是固定網址。

### 心夜要做的一次設定

1. 用要綁定的 GitHub 帳號登入 [Vercel](https://vercel.com)，選 **Add New… → Project**，匯入 `blackprince0427-droid/OMB`。
2. **Root Directory** 設為 `web`。應用放在這個英文目錄，是因為路徑裡的「網頁版」會讓 Turbopack 在建置時當掉。倉庫根目錄沒有 `package.json`，不設 Root Directory 就不會辨認成 Next.js。
3. Framework Preset 維持 **Next.js**。Build Command 用 `npm run build`，Install Command 用 `npm install`。這兩項已寫在 `web/vercel.json`。不要改 Output Directory。
4. **不需要環境變數。** Node.js 用 20.9 或更新（`package.json` 的 `engines`）。
5. Production Branch 選 `main`。確認 Git 自動部署是開的（Vercel 匯入 GitHub 倉庫後的預設）。
6. 按 Deploy。第一次部署的是當時 `main` 上的程式。之後只要有人把變更合併進 `main`，同一個網址會自動換成新版本。

如果這個 Vercel 專案先前已把 Root Directory 設成 `網頁版`，合併後改成 `web`，再按 Redeploy。中文目錄會讓 Turbopack 建置失敗。

本機 `npm start` 仍綁在 43123，只給自己開機用。Vercel 不走這條指令，改由它自己的 Next.js 執行環境提供網站。

## 第一版做了什麼

- 登入。未登入不能進入主框架。預設帳戶與密碼都是 `CEO`。
- 角色：CEO、HR、會計、員工。角色只在新增使用者時寫入。
- CEO 可新增使用者。其他角色看不到「使用者」入口；直接打開該頁會看到沒有權限。
- 主框架：導覽、目前使用者、日曆入口。
- 月視圖日曆：七欄、星期日開始、標示今天、上一月、下一月、回到今天。沒有事件。

## 第二版做了什麼

依據 `開發文檔/第二版內容_DEV-V2-CONTENT_20261008.md`。

- CEO 與 HR 可新增部門，並在指定部門新增職位。職位要填名稱與順序數字，數字較大者為較高職位。
- CEO 與 HR 可把帳戶指派到部門，並指定該部門的一個職位。一人可屬多個部門。再次指派同一部門會改為新的職位。
- CEO 與 HR 可記錄個別權限。這項記錄不覆蓋職位順序。
- 每個帳戶只能新增與修改自己的工作紀錄。
- 同一部門內，順序數字較大的職位可以查詢較低職位的工作紀錄，不能修改，也不能跨部門查詢。
- 部門、職位、指派、個別權限與工作紀錄存在這個瀏覽器的 `localStorage`，鍵名分別是 `osp-dev-v2-departments`、`osp-dev-v2-positions`、`osp-dev-v2-assignments`、`osp-dev-v2-permissions`、`osp-dev-v2-records`。

## 第三版做了什麼

依據 `開發文檔/第三版內容_DEV-V3-CONTENT_20261008.md`。

- 使用者可在「帳戶」更改自己的密碼，須輸入舊密碼與新密碼。更改後仍保持登入。可登出並返回登入頁。
- CEO 與 HR 可更改使用者在已屬部門內的職位，須指定部門。儲存後查詢範圍按新職位立即計算。這個畫面不把帳戶加進新部門。
- 工作紀錄每次顯示 10 筆。按日期搜尋後只顯示當天；當天超過 10 筆仍按 10 筆分頁。查詢較低職位的紀錄同樣每次 10 筆，也可按日期搜尋。
- 「未完成工作」只顯示本人未完成項目。標為已完成後離開該頁，紀錄仍留在工作紀錄，並標為已完成。
- 早前沒有日期或完成狀態的工作紀錄，讀取時會把更新日期的日期部分當作工作日期，並視為未完成。

## 第四版做了什麼

依據 `開發文檔/第四版內容_DEV-V4-CONTENT_20261009.md`。

- 開發者後台在 `/console`。公司網站的導覽、總覽與登入頁都沒有後台入口。
- 後台可按公司名稱停用公司。公司與原有資料仍保留。本版不能重新啟用。
- 每家公司的帳戶、部門、職位、工作紀錄與操作日誌各自存放，不能在另一家公司的網站看到。

## 第五版修復了什麼

依據 `開發文檔/第五版修復_DEV-V5-FIX_20261009.md`。

- 建立公司時必須同時建立初始 CEO。帳戶只寫入該公司。新帳戶不得使用 `CEO` 同時作為帳戶與密碼，初始密碼在建立時設定。
- 後台使用獨立開發人員登入，不使用公司帳戶。預設帳戶與密碼都是 `開發人員`。登入狀態存在 `sessionStorage`（鍵名 `osp-dev-v5-dev-session`）。
- 公司網站對應前端。一個網址只載入網站相符的公司。預設公司使用根路徑。新公司可填一層路徑，例如 `/acme`，或填 http(s) 網址；寫了主機時，主機也必須相同。
- 停用公司立即生效。該公司已登入的工作階段在下次操作時不能繼續，資料仍保留。
- 同一部門內職位順序相同，不可互相查詢，只可查詢較低職位。
- 更改職位只改已屬部門的職位，不會在這個動作加入新部門。
- 後台可只讀查看所選公司的日誌，不能修改或刪除。公司網站不出現日誌。

## 第六版做了什麼

依據 `開發文檔/第六版內容_DEV-V6-CONTENT_20261010.md`（計劃書 V1.24）。仍是單機客戶端。跨人是指同一瀏覽器輪流登入後可見，不是即時多人協作。

- CEO 與 HR 可在「權限指派」調整帳戶角色或個別權限。儲存後登出再登入，設定仍在。公司至少保留一位 CEO。
- 個別權限可覆蓋同一部門的職位順序。覆蓋開啟後，可見範圍以勾選的同部門帳戶為準，可放寬或收斂，不因此開放跨部門。覆蓋關閉時，查詢規則與第五版相同，同階不可互查。
- 工作紀錄可指定歸屬。分交會改歸屬：新歸屬者可以修改，原歸屬者不能再改。只有目前歸屬者可以分交。沒有即時通知。
- 「未完成工作」另有跨人待辦：別人指給我的可以完成，我可見的只可查看。

## 第七版做了什麼

依據 `開發文檔/第七版內容_DEV-V7-CONTENT_20261010.md`（計劃書 V1.25）。任務樹取代第六版的單一專案標籤。仍是單機客戶端。跨人是同一瀏覽器輪流登入。

- 已登入帳戶可建立專案（L0）。節點負責人可在該節點下建立下一層，到工作項（L3）為止，不能再拆，也不能在這一頁建立同層。
- 每層有四種狀態：未開始、進行中、已完成、暫停。改一層不會改其他層。
- 添加負責人與轉交都要對方同意。請求出現在對方的「未完成工作」。同意前邀請人可撤回。拒絕後顯示「已拒絕」，負責人不變。轉交成功後，原負責人只剩查看，節點狀態不變。
- 只有專案建立者可以刪除整棵樹。整棵樹進「刪除頁面」，還原時狀態和邀請一起回來。底下已有子節點時，不能單獨刪掉上層。
- 專案頁預設展開主任務，子任務與工作項要手動展開。畫面上有名稱、狀態、負責人摘要。
- 專案負責人可設全專案可見、部分可見或只限自己部分，而且始終看得到整棵樹。部分可見時，名單外的人看不到節點；節點負責人仍看得到自己的節點和上層。名單上的人只能看。
- 每個節點可加待辦備註和連結。勾完備註不改節點狀態。連結可調整順序，點了會開網址。
- 節點改成已完成時，該層寫一筆工作紀錄，只有標題和層級。未完成的任務列在「未完成工作」，點名稱打開節點。點工作紀錄時若無權進入，畫面顯示無權限，紀錄仍保留。
- 介面把未完成工作、專案、工作紀錄、刪除頁面收成側欄的「工作」，用頁內分頁切換。各分頁內容與調整前相同。說明見 `開發文檔/第七版附加_UI設計調整_20261010.md`。
