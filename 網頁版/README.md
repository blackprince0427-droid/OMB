# 小型辦公軟件

網頁版，對應 OMB 開發文檔 DEV-V1、UI 規格 UI-DEV-V1、第二版內容 DEV-V2-CONTENT（依據計劃書 V1.14）、第三版內容 DEV-V3-CONTENT（依據計劃書 V1.16），第四版內容 DEV-V4-CONTENT（依據計劃書 V1.20），以及第五版修復 DEV-V5-FIX（依據計劃書 V1.22）。桌面版先不做。

## 開啟

用瀏覽器打開 [http://localhost:43123](http://localhost:43123)。預設帳戶與密碼都是 `CEO`。

網頁若尚未啟動，在專案目錄執行：

```bash
npm install
npm run open
```

目前這個網站的資料屬於「預設公司」，預設帳戶與密碼都是 `CEO`。登入狀態存在 `sessionStorage`（鍵名 `osp-dev-v1-session`），留在目前這個分頁。可在「帳戶」登出並返回登入頁。公司、各公司的帳戶與工作資料存在 `localStorage`，鍵名是 `osp-dev-v4-companies` 與 `osp-dev-v4-bundles`。清除這個網站的資料後，會回到預設公司的 CEO 帳戶。

## 第一版做了什麼

- 登入。未登入不能進入主框架。預設帳戶與密碼都是 `CEO`。
- 角色：CEO、HR、會計、員工。角色只在新增使用者時寫入。
- CEO 可新增使用者。其他角色看不到「使用者」入口；直接打開該頁會看到沒有權限。
- 主框架：導覽、目前使用者、日曆入口。
- 月視圖日曆：七欄、星期日開始、標示今天、上一月、下一月、回到今天。沒有事件。

## 第二版做了什麼

依據 `開發文檔/第二版內容_DEV-V2-CONTENT_20261008.md`。

- CEO 與 HR 可新增部門，並在指定部門新增職位。職位要填名稱與順序數字，數字較大者為較高職位。
- CEO 與 HR 可把帳戶指派到部門，並指定該部門的一個職位。一人可屬多個部門。再次指派同一部門會改為新的職位。
- CEO 與 HR 可記錄個別權限。這項記錄不覆蓋職位順序。
- 每個帳戶只能新增與修改自己的工作紀錄。
- 同一部門內，順序數字較大的職位可以查詢較低職位的工作紀錄，不能修改，也不能跨部門查詢。
- 部門、職位、指派、個別權限與工作紀錄存在這個瀏覽器的 `localStorage`，鍵名分別是 `osp-dev-v2-departments`、`osp-dev-v2-positions`、`osp-dev-v2-assignments`、`osp-dev-v2-permissions`、`osp-dev-v2-records`。

## 第三版做了什麼

依據 `開發文檔/第三版內容_DEV-V3-CONTENT_20261008.md`。

- 使用者可在「帳戶」更改自己的密碼，須輸入舊密碼與新密碼。更改後仍保持登入。可登出並返回登入頁。
- CEO 與 HR 可更改使用者在已屬部門內的職位，須指定部門。儲存後查詢範圍按新職位立即計算。這個畫面不把帳戶加進新部門。
- 工作紀錄每次顯示 10 筆。按日期搜尋後只顯示當天；當天超過 10 筆仍按 10 筆分頁。查詢較低職位的紀錄同樣每次 10 筆，也可按日期搜尋。
- 「未完成工作」只顯示本人未完成項目。標為已完成後離開該頁，紀錄仍留在工作紀錄，並標為已完成。
- 早前沒有日期或完成狀態的工作紀錄，讀取時會把更新日期的日期部分當作工作日期，並視為未完成。

## 第四版做了什麼

依據 `開發文檔/第四版內容_DEV-V4-CONTENT_20261009.md`。

- 開發者後台在 `/console`。公司網站的導覽、總覽與登入頁都沒有後台入口。
- 後台可按公司名稱停用公司。公司與原有資料仍保留。本版不能重新啟用。
- 每家公司的帳戶、部門、職位、工作紀錄與操作日誌各自存放，不能在另一家公司的網站看到。

## 第五版修復了什麼

依據 `開發文檔/第五版修復_DEV-V5-FIX_20261009.md`。

- 建立公司時必須同時建立初始 CEO。帳戶只寫入該公司。新帳戶不得使用 `CEO` 同時作為帳戶與密碼，初始密碼在建立時設定。
- 後台使用獨立開發人員登入，不使用公司帳戶。預設帳戶與密碼都是 `開發人員`。登入狀態存在 `sessionStorage`（鍵名 `osp-dev-v5-dev-session`）。
- 公司網站對應前端。一個網址只載入網站相符的公司。預設公司使用根路徑。新公司可填一層路徑，例如 `/acme`，或填 http(s) 網址；寫了主機時，主機也必須相同。
- 停用公司立即生效。該公司已登入的工作階段在下次操作時不能繼續，資料仍保留。
- 同一部門內職位順序相同，不可互相查詢，只可查詢較低職位。
- 更改職位只改已屬部門的職位，不會在這個動作加入新部門。
- 後台可只讀查看所選公司的日誌，不能修改或刪除。公司網站不出現日誌。

## 本版不做

次日通知、以個別權限覆蓋職位順序、從月視圖進入工作紀錄。角色指派畫面、個人事項與審批路徑仍未納入。原型裡的「原型重置」未納入。

```bash
npm test
```
