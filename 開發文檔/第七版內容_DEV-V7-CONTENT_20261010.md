| 項目 | 內容 |
| --- | --- |
| 誰 | 可改該節點的負責人（建改走負責人規則，見第 5、6 節）。系統不代改其他層。 |

- [ ] 上層改狀態後，下層狀態保持原值。

## 4. 負責人／添加／轉交

- 每層皆有狀態欄＋負責人（可多人、可空）。
- 添加負責人／轉交：對方**必須同意**，不能強行。
- 請求進對方待辦或通知區；輪流帳戶登入後同意／拒絕。
- 同意前邀請人可撤回。
- 拒絕：邀請人見「已拒絕」；負責人不變；可再邀請同一人或換人。
- 轉交成功：原負責人自動移除、變成僅可見；節點狀態不變。

### 4.1 可執行規格

| 項目 | 內容 |
| --- | --- |
| 誰 | 每層節點都有負責人，可多人，也可空。添加與轉交走負責人規則（第 6 節：可見名單僅可看）。被邀請的帳戶決定同意或拒絕。 |
| 做什麼 | 添加負責人、轉交都先送請求。請求進入對方待辦或通知區。對方以輪流登入同意或拒絕。同意前，邀請人可撤回。 |
| 輸入 | 目標節點；被邀請帳戶；動作是添加或轉交。 |
| 輸出 | 同意添加：該帳戶成為負責人。同意轉交：原負責人自動移除並變成僅可見，節點狀態不變。拒絕：邀請人看到「已拒絕」，負責人不變。撤回：該次請求取消。 |
| 邊界 | 不能強行添加或轉交。拒絕後可再邀請同一人，或改邀別人。無即時推播；對方要輪流登入才看得到請求。跨公司不在本版。 |

### 4.2 檢查清單

- [ ] 每層都有狀態欄與負責人；負責人可以多人，也可以空著。
- [ ] 添加或轉交在對方同意前不生效，不能強行寫入。
- [ ] 請求出現在對方待辦或通知區；以登出再換帳戶登入可同意或拒絕。
- [ ] 對方尚未同意時，邀請人可撤回。
- [ ] 拒絕後，邀請人看得到「已拒絕」，負責人維持不變；可再邀同一人或換人。
- [ ] 轉交同意後，原負責人被移除且只剩可見，節點狀態與轉交前相同。

## 5. 建刪／權限

- 負責人可建**下一層**，不能建**同層**；不需專案負責人授權。
- 任何人可建專案；只能刪**自己建**的專案；有子節點不能刪上層。
- 刪專案＝整棵樹進「刪除頁面」存放；可還原（狀態＋邀請狀態一併帶回）。
- 名稱所有層級均可重複；可建多個專案且可同步進行。
- 專案頁：預設展開 L1，L2／L3 手動展開；顯示名稱、狀態、負責人摘要。

### 5.1 可執行規格

| 項目 | 內容 |
| --- | --- |
| 誰 | 任何人可建專案（L0）。節點負責人可在自己負責的節點下建下一層，不需要專案負責人再授權。刪專案只限該專案的建立者。 |
| 做什麼 | 建立下一層節點。刪除自己建立的專案時，整棵樹移入刪除頁面，並可還原。有子節點時，不能單獨刪掉上層。 |
| 輸入 | 建專案：專案名稱。建下一層：父節點＋新節點名稱。刪專案：自己建立的該專案。還原：刪除頁面中的該棵樹。 |
| 輸出 | 新節點；或刪除頁面中的整棵樹。還原後樹結構、節點狀態與邀請狀態一起回來。專案頁列出名稱、狀態、負責人摘要。 |
| 邊界 | 不能建同層。不能刪別人建立的專案。有子節點時不得單獨刪除上層而留下子節點；刪專案是整棵樹一併進刪除頁面。名稱可重複。多個專案可同時進行。專案頁預設展開 L1，L2／L3 預設不展開。 |

### 5.2 檢查清單

- [ ] 任一已登入帳戶都可新建專案。
- [ ] 負責人可建立下一層，不能建立同層，且不必另得專案負責人授權。
- [ ] 不能刪除別人建立的專案。
- [ ] 節點底下已有子節點時，不能單獨刪除該上層節點。
- [ ] 刪除自己建立的專案後，整棵樹出現在刪除頁面；還原後狀態與邀請狀態都在。
- [ ] 專案頁打開時 L1 已展開，L2／L3 需手動展開；畫面上有名稱、狀態、負責人摘要。

## 6. 可見範圍（專案負責人設定）

專案負責人可設定：

1. 全專案可見
2. 部分可見（勾選可見人員名單；外人看不到任何節點）
3. 只限自己部分

專案負責人永遠可見整棵樹。可見名單僅可看；建改節點與邀請走負責人規則。

### 6.1 產品翟清（心夜已拍板，必寫）

部分可見時：負責人至少可見**自己負責的節點及其上層**（即使未進可見名單，負責人對自己的節點與路徑上層仍有可見權）。

### 6.2 可執行規格

| 項目 | 內容 |
| --- | --- |
| 誰 | 專案負責人設定本專案可見範圍。專案負責人永遠看得到整棵樹。 |
| 做什麼 | 三選一：全專案可見；部分可見（勾選可見人員名單）；只限自己部分。部分可見時，名單外的人看不到任何節點，但負責人仍看得到自己負責的節點以及通往該節點的上層。 |
| 輸入 | 可見模式；部分可見時的可見人員名單。 |
| 輸出 | 各帳戶打開專案時，只看到規則允許的節點。可見名單上的人只能看，不能藉此取得建改或邀請權。 |
| 邊界 | 建節點、改節點、邀請仍走負責人規則，不因在可見名單上而放寬。外人（未進部分可見名單、且不是「自己節點及上層」的負責人）看不到任何節點。本規則以輪流登入驗收。 |

### 6.3 檢查清單

- [ ] 專案負責人可把可見範圍設成全專案可見、部分可見或只限自己部分。
- [ ] 專案負責人在三種設定下都看得到整棵樹。
- [ ] 部分可見時，未在名單上的外人看不到任何節點。
- [ ] 部分可見時，某節點負責人即使不在可見名單，仍看得到自己負責的節點及其上層。
- [ ] 只在可見名單上的人可以看，不能建改節點，也不能發出邀請。

## 7. 備註與連結

- 待辦＝節點備註清單（標題＋完成）；L0～L3 皆可加；不算第四層；完成不改節點狀態。
- 超連結＝節點連結清單（類似備註）；不設上限；允許調整位置；無獨立負責人／狀態；權限跟節點；點開網址。

### 7.1 可執行規格

| 項目 | 內容 |
| --- | --- |
| 誰 | 能建改該節點的負責人，可在該節點上加備註與連結。看得到該節點的人，依節點權限使用這些清單。 |
| 做什麼 | 每個節點有一份待辦（備註清單：標題＋完成）和一份連結清單。兩份都掛在節點上，不成為 L4。 |
| 輸入 | 備註標題，以及是否完成。連結網址；清單中的位置順序。 |
| 輸出 | 節點上的備註清單與連結清單。勾完備註只改該則備註，不改節點四態。點連結開該網址。 |
| 邊界 | 備註與連結沒有獨立負責人、沒有獨立狀態。連結數量不設上限，順序可調。權限與所屬節點相同。完成備註不觸發第 8 節的節點完成寫入。 |

### 7.2 檢查清單

- [ ] L0～L3 每個節點都能加待辦備註（標題＋完成）。
- [ ] 備註勾完成後，節點狀態不變，樹的層數也不增加。
- [ ] 每個節點都能加連結；連結可以多筆，順序可以調整。
- [ ] 連結沒有自己的負責人或狀態；點了會開網址。
- [ ] 看不到該節點的人，也看不到該節點的備註與連結。

## 8. 工作紀錄同步

- 每層節點完成各自寫一筆工作紀錄。
- 未完成出現「未完成工作」；點擊轉跳對應節點頁。
- 工作紀錄僅標題＋層級。
- 產品翟清（心夜已拍板，必寫）：工作紀錄點標題若無權進節點，則顯示無權限；**不刪除**該筆工作紀錄。

### 8.1 可執行規格

| 項目 | 內容 |
| --- | --- |
| 誰 | 節點被標成完成時，由系統在本機寫入一筆工作紀錄。登入者在工作紀錄與「未完成工作」中看到規則允許的項目。 |
| 做什麼 | L0～L3 每一層完成，各寫一筆工作紀錄，內容只有標題＋層級。尚未完成的節點出現在「未完成工作」；點標題轉到該節點頁。 |
| 輸入 | 節點完成（該節點狀態成為已完成）；或節點仍未完成。工作紀錄標題取節點名稱，層級取 L0～L3。 |
| 輸出 | 一筆僅含標題與層級的工作紀錄；或一筆「未完成工作」入口。點標題：有權則進入節點頁；無權則顯示無權限。 |
| 邊界 | 不因無權查看節點而刪除已寫入的工作紀錄。各層各自一筆，不合併成只記 L3。本同步依賴任務樹（F-29）已存在。單機、輪流登入；沒有即時同時編輯。 |

### 8.2 檢查清單

- [ ] L0、L1、L2、L3 各自完成時，各產生一筆工作紀錄。
- [ ] 該筆工作紀錄只有標題與層級。
- [ ] 未完成的節點會出現在「未完成工作」；點了會轉到對應節點頁。
- [ ] 點工作紀錄標題時，若此帳戶無權進入該節點，畫面顯示無權限。
- [ ] 顯示無權限之後，該筆工作紀錄仍在，沒有被刪除。
