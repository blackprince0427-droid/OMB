# 第七版附加：UI 設計調整

- 文件編號：DEV-V7-UI
- 日期：2026-10-10
- 性質：介面編排。附在第七版內容之後。
- 不新增承諾編號。F-29、F-30 的產品規則不改。
- 依據：心夜於 2026-10-10 確認的分頁預覽。
- 說明：含工作分頁編排，以及專案頁任務樹顯示切換（密集表／卡片看板，第 5 節）。

## 1. 調整了什麼

側欄「營運」原本有四個入口：工作紀錄、未完成工作、專案、刪除頁面。改成一個入口，名稱是「工作」。

進入後，頁面標題是「工作」。上方第一行三個分頁，順序固定為：

1. 工作紀錄
2. 未完成工作
3. 專案

有專案時，下一行才出現「刪除紀錄」。沒有專案時不顯示。自己刪過、還沒還原的專案也算，避免還原入口消失。側欄「工作」預設打開工作紀錄。

總覽的常用功能裡，這三個捷徑收成同一個「工作」。

手機上，第一行分頁放不下時可左右滑。「刪除紀錄」另起一行。不另做底欄。

## 2. 每個分頁裡有什麼

各分頁沿用調整前該頁的內容與操作。

| 分頁 | 沿用的內容 |
| --- | --- |
| 未完成工作 | 自己的未完成、別人指給我的、我可見的、待處理邀請、未完成的任務 |
| 專案 | 建立專案、任務樹、打開節點後的狀態、下一層、邀請、備註、連結、可見範圍、刪除 |
| 工作紀錄 | 新增、分交、歸屬我的列表（每次 10 筆）、任務完成紀錄、查詢可見的紀錄 |
| 刪除紀錄 | 自己刪除的整棵專案樹，以及還原。沒有專案時不顯示這個入口。 |

打開節點時，人留在「工作」這一頁，分頁停在「專案」。從「未完成的任務」或「任務完成紀錄」點標題，同樣切到「專案」分頁並打開該節點。看不到節點時仍顯示無權限，該筆工作紀錄不刪除。

## 3. 網址

四個分頁仍使用原來的路徑，方便直接打開：

| 分頁 | 路徑 |
| --- | --- |
| 工作紀錄 | `/records` |
| 未完成工作 | `/pending` |
| 專案 | `/projects` |
| 刪除紀錄 | `/deleted` |

公司網站會在路徑前加上該公司的網站路徑。側欄「工作」預設打開工作紀錄。

## 4. 這次不改

- 不改誰可以建立、查看、邀請、刪除或還原。
- 不改任務樹層級、狀態、同意後才生效的邀請。
- 不改工作紀錄每次 10 筆，也不把工作紀錄放進月視圖。
- 不做左右欄工作台，也不把未完成項目收成只跟當前節點有關的清單。

## 5. 任務樹顯示方式：密集表／卡片看板

專案頁的任務樹（含打開某個專案後的樹）同時支援兩種顯示方式：**密集表**、**卡片看板**。這是 F-29 專案頁的顯示方式，附在本文件。不開新的承諾編號（不開 F-31）。F-29、F-30 的產品規則不改。

兩種模式共用同一份任務樹資料，權限仍按 F-29。不是兩套資料。

### 5.1 誰可以切換

能看見該專案或節點的人，在專案頁都能切換顯示方式。顯示偏好是本機、帳戶級：跟目前登入的帳戶走，存在這台機器上。不寫進任務樹資料，也不改變誰可以看、建、邀請、刪除或還原。

### 5.2 切換

位置在頁面頭部：專案摘要下方的工具列，用分段控件二選一（密集表、卡片看板）。

- 預設是密集表。
- 切換後記住上次的模式。同一帳戶下次打開專案頁，沿用上次；沒有記錄時用密集表。
- 切換無重載：不重新整理整頁，也不跳路徑。人留在專案頁。
- 原型用 localStorage 記住這一個顯示方式。產品約束仍是單機本機儲存，不上傳、不跟別人同步。

### 5.3 密集表

表格一列一個節點。欄位是：層級／名稱、狀態、可見範圍、負責人、備註、超連結。

展開對齊現有規則（DEV-V7「專案頁：預設展開 L1」）：預設展開至 L1；L2、L3 手動展開。

### 5.4 卡片看板

- 預設依 L1 主任務分泳道。泳道內是 L2 卡片，卡片可展開見 L3。
- 可改為依狀態泳道。四條泳道固定為：未開始、進行中、已完成、暫停。泳道內仍是 L2 卡片，可展開見 L3。
- 看板內仍顯示節點摘要：狀態、負責人、備註、連結，以及可見範圍等同一份節點上已有的欄位。
- 記住的是「密集表或卡片看板」。泳道分法可在看板內切換，預設依 L1 主任務。

### 5.5 不做

- 甘特圖。
- 拖拉排程。
- 跨公司。
- 即時協作。

- [ ] 切換後，同一帳戶再開仍是上次的模式；偏好在本機、跟帳戶走，不改權限。
- [ ] 切換時整頁不重載，網址路徑不變。
