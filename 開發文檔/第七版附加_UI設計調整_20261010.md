# 第七版附加：UI 設計調整

- 文件編號：DEV-V7-UI
- 日期：2026-10-10
- 性質：介面編排。附在第七版內容之後。
- 不新增承諾編號。F-29、F-30 的產品規則不改。
- 依據：心夜於 2026-10-10 確認的分頁預覽。

## 1. 調整了什麼

側欄「營運」原本有四個入口：工作紀錄、未完成工作、專案、刪除頁面。改成一個入口，名稱是「工作」。

進入後，頁面標題是「工作」。上方有四個分頁，順序固定為：

1. 未完成工作
2. 專案
3. 工作紀錄
4. 刪除頁面

總覽的常用功能裡，這三個捷徑收成同一個「工作」。

手機上，四個分頁在標題下方橫向排列，放不下時可左右滑。不另做底欄。

## 2. 每個分頁裡有什麼

各分頁沿用調整前該頁的內容與操作。

| 分頁 | 沿用的內容 |
| --- | --- |
| 未完成工作 | 自己的未完成、別人指給我的、我可見的、待處理邀請、未完成的任務 |
| 專案 | 建立專案、任務樹、打開節點後的狀態、下一層、邀請、備註、連結、可見範圍、刪除 |
| 工作紀錄 | 新增、分交、歸屬我的列表（每次 10 筆）、任務完成紀錄、查詢可見的紀錄 |
| 刪除頁面 | 自己刪除的整棵專案樹，以及還原 |

打開節點時，人留在「工作」這一頁，分頁停在「專案」。從「未完成的任務」或「任務完成紀錄」點標題，同樣切到「專案」分頁並打開該節點。看不到節點時仍顯示無權限，該筆工作紀錄不刪除。

## 3. 網址

四個分頁仍使用原來的路徑，方便直接打開：

| 分頁 | 路徑 |
| --- | --- |
| 未完成工作 | `/pending` |
| 專案 | `/projects` |
| 工作紀錄 | `/records` |
| 刪除頁面 | `/deleted` |

公司網站會在路徑前加上該公司的網站路徑。側欄「工作」預設打開未完成工作。

## 4. 這次不改

- 不改誰可以建立、查看、邀請、刪除或還原。
- 不改任務樹層級、狀態、同意後才生效的邀請。
- 不改工作紀錄每次 10 筆，也不把工作紀錄放進月視圖。
- 不做左右欄工作台，也不把未完成項目收成只跟當前節點有關的清單。
